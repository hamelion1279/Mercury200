# Wi-Fi репитер на ESP32-S3

Прошивка превращает ESP32-S3 в **повторитель Wi-Fi** (репитер / усилитель):
устройство **принимает одну сеть** (подключается к ней как клиент) и
**раздаёт другую** — свою собственную сеть для ваших устройств.
Интернет клиентам отдаётся через NAT, то есть отдельный роутер не нужен.

```
   [ роутер, внешняя сеть ]              [ ESP32-S3 ]                [ ваши устройства ]
      SSID: MyWiFi                 <---  Wi-Fi STA  |  Wi-Fi SoftAP  --->   SSID: MyWiFi-EXT
      192.168.1.1                      192.168.1.50   192.168.4.1          192.168.4.x
                                                    NAT + DNS
```

Настройка целиком в `menuconfig` (или в `sdkconfig.defaults`), прошивается
через обычный `idf.py flash`, после запуска работает самостоятельно:
ищет сеть, подключается, включает NAT, сама восстанавливает связь.

---

## 1. Что нужно

* плата на **ESP32-S3** (любая: DevKitC-1, YD-ESP32-S3, Super Mini и т. п.);
* **ESP-IDF v5.5** или **v6.x** (прошивка проверяется сборкой на обоих);
* кабель USB и драйвер USB-UART (у большинства плат S3 — нативный USB).

Внешняя сеть обязательно должна быть в диапазоне **2,4 ГГц** — ESP32-S3
не умеет 5 ГГц.

## 2. Быстрый старт

```bash
# 1) установить ESP-IDF (если ещё не установлен), например v5.5
mkdir -p ~/esp && cd ~/esp
git clone -b v5.5 --depth 1 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3 && . ./export.sh

# 2) перейти в проект
cd /путь/к/Mercury200/esp32/wifi-repeater

# 3) задать свою сеть и пароль
idf.py set-target esp32s3
idf.py menuconfig          # раздел "Wi-Fi repeater (ESP32-S3)"

# 4) собрать, прошить, смотреть лог
idf.py -p /dev/ttyUSB0 flash monitor      # для Windows: -p COM5
```

В `menuconfig` минимально нужно поменять:

| Пункт | Что вписать |
| --- | --- |
| Принимаемая (внешняя) сеть → **Имя внешней Wi-Fi сети (SSID)** | SSID сети, которую принимаем |
| Принимаемая (внешняя) сеть → **Пароль внешней сети** | её пароль |
| Своя (раздаваемая) сеть → **Пароль своей сети** | пароль для ваших устройств (от 8 символов) |

Остальное можно оставить по умолчанию: своя сеть получит имя
`<имя внешней сети>-EXT`, адрес `192.168.4.1`, канал — как у внешней сети.

Выйти из монитора — `Ctrl+]`.

### Готовая прошивка (если не хочется собирать самому)

В репозитории есть сборка в GitHub Actions (`.github/workflows/firmware.yml`,
проект собирается сразу на ESP-IDF v5.5 и v6.x). Готовые файлы лежат в
**Actions → последний запуск «ESP32-S3 firmware» → Artifacts**:

* `esp32s3-wifi-repeater-merged.bin` — **единый образ**, прошивается целиком
  по адресу `0x0` одной командой:

  ```bash
  esptool.py --chip esp32s3 write_flash 0x0 esp32s3-wifi-repeater-merged.bin
  ```

  (это же подходит для «ESP32 Flash Download Tool» из Windows: адрес `0x0`);
* `wifi-repeater.bin` + `bootloader.bin` + `partition-table.bin` — образы
  по отдельности, если прошивать через `idf.py flash`.

  Важно: в артефакте — прошивка с настройками по умолчанию
  (внешняя сеть `MyWiFi`, своя сеть с паролем `repeater-ext`). Чтобы репитер
  подключался к **вашей** сети, задайте SSID и пароль в `menuconfig`
  и соберите прошивку сами (шаги 3–4 выше).

## 3. Основные настройки

Все параметры находятся в `menuconfig` → **Wi-Fi repeater (ESP32-S3)**.

### Принимаемая (внешняя) сеть, режим станции

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `REPEATER_UPSTREAM_SSID` | `MyWiFi` | SSID внешней сети (что принимаем) |
| `REPEATER_UPSTREAM_PASSWORD` | пусто | пароль внешней сети |
| `REPEATER_UPSTREAM_BSSID` | пусто | привязка к конкретной точке доступа `AA:BB:CC:DD:EE:FF` (для mesh из нескольких точек с одним SSID) |
| `REPEATER_UPSTREAM_AUTHMODE_THRESHOLD` | WPA2 | минимальное шифрование; для открытой сети выберите `OPEN` |
| `REPEATER_RESCAN_PERIOD` | 30 с | как часто искать сеть, пока связи нет |

### Своя (раздаваемая) сеть, режим точки доступа

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `REPEATER_AP_SSID` | пусто | имя своей сети; пусто = `<SSID внешней сети>-EXT`. Можно задать то же имя, что и у внешней сети |
| `REPEATER_AP_PASSWORD` | `repeater-ext` | пароль своей сети; пусто = открытая сеть. **Обязательно поменяйте!** |
| `REPEATER_AP_CHANNEL` | 0 | 0 = канал как у внешней сети (правильно для репитера) |
| `REPEATER_AP_MAX_STA` | 4 | максимум клиентов (1…10) |
| `REPEATER_AP_HIDDEN` | нет | скрыть имя своей сети |
| `REPEATER_AP_IP` / `REPEATER_AP_NETMASK` | `192.168.4.1` / `255.255.255.0` | адрес репитера в своей сети |
| `REPEATER_AP_DNS` | пусто | DNS для клиентов; пусто = DNS внешней сети |

### Прочее

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `REPEATER_HOSTNAME` | `esp32-repeater` | имя устройства в списке клиентов роутера |
| `REPEATER_STATUS_LOG_PERIOD` | 60 с | период отчёта о состоянии в лог (0 = выключить) |
| `REPEATER_STATUS_LED_GPIO` | -1 | вывод светодиода статуса (-1 = нет). Горит — интернет есть, мигает — связи нет |

Секция настроек генерируется файлом `main/Kconfig.projbuild`.

## 4. Как проверить, что всё работает

1. В мониторе должно появиться что-то вроде:

```
I (1234) repeater: Найдена "MyWiFi": канал 6, RSSI -52 дБм, BSSID aa:bb:cc:dd:ee:ff
I (1400) repeater: Своя сеть: "MyWiFi-EXT", канал 6, до 4 клиентов
I (2500) repeater: Подключились к "MyWiFi": канал 6, BSSID ...
I (3100) repeater: Получен IP от внешней сети: 192.168.1.50, шлюз 192.168.1.1
I (3200) repeater: Клиенты получат DNS 192.168.1.1
I (3300) repeater: NAT (NAPT) включён — клиенты своей сети выходят в интернет
```

2. Подключите телефон/ноутбук к сети `MyWiFi-EXT` — адрес должен быть
   из подсети репитера (`192.168.4.x`), интернет — работать.
3. Проверьте скорость и уровень сигнала:

```
I (63000) repeater: Статус: внешняя сеть "MyWiFi", канал 6, RSSI -52 дБм | своя сеть "MyWiFi-EXT", клиентов 2 | NAT включён
```

## 5. Важные ограничения (одно радио)

* **Один канал и одна антенна.** ESP32-S3 имеет одно Wi-Fi-радио, поэтому
  приём и раздача идут по очереди на одном канале: реальная скорость для
  клиента примерно **вдвое меньше**, чем скорость подключения к роутеру.
  Ставьте репитер в зоне, где сигнал внешней сети уверенный (RSSI лучше −70 дБм).
* **Канал своей сети = канал внешней сети.** Драйвер автоматически
  переводит свою точку доступа на канал подключения. Если внешняя сеть
  сменит канал, клиенты репитера кратко потеряют связь.
* **Только 2,4 ГГц.** Если у роутера отдельные SSID для 2,4 и 5 ГГц —
  в настройках репитера указывайте 2,4-гигагерцевый.
* **Широковещательные протоколы не проходят через NAT:** mDNS/Bonjour,
  DLNA, обнаружение принтеров и т. п. могут не работать.
* **IPv6 не маршрутизируется** — используется только IPv4.
* Клиенты своей сети не видят устройства внешней сети напрямую
  (как за любым NAT), если в каталоге `esp32/` не сказано иное.

## 6. Если не работает

| Симптом | Причина и решение |
| --- | --- |
| `Связь потеряна ... неверный пароль` (код 15/202) | проверьте пароль внешней сети, тип шифрования (`REPEATER_UPSTREAM_AUTHMODE_THRESHOLD`) |
| `сеть не найдена: слишком далеко` (код 201) | внешняя сеть вне зоны/5 ГГц/скрытая — поднесите плату ближе, проверьте SSID |
| `её шифрование слабее заданного порога` (код 211) | для открытой/WEP-сети выберите в menuconfig соответствующий порог (OPEN/WEP) |
| Клиенты подключаются, но интернета нет | 1) проверьте, что `CONFIG_LWIP_IP_FORWARD=y` и `CONFIG_LWIP_IPV4_NAPT=y` (задано в `sdkconfig.defaults`); 2) убедитесь, что подсеть репитера (`192.168.4.0/24`) не совпадает с подсетью внешней сети — при совпадении поменяйте `REPEATER_AP_IP`, например на `192.168.50.1` |
| Имена сайтов не открываются по IP-адресам, а по именам — нет | DNS: внешняя сеть не отдала DNS. Задайте `REPEATER_AP_DNS`, например `1.1.1.1` |
| Роутер «не видит» репитер | смотрите MAC станции в логе в самом начале и ищите его в списке клиентов роутера |
| Прошивка не собирается из-за `sdkconfig.defaults` | если что-то менялось вручную, удалите `sdkconfig` и соберите заново (файл `sdkconfig.defaults` применяется только при его отсутствии) |

## 7. Как устроено (для любопытных)

* `main/main.c` — вся логика: сканирование внешней сети, режим `APSTA`,
  NAT (NAPT) и IP-форвардинг, раздача DNS по DHCP, задача сопровождения
  (переподключение с задержкой, поиск сети раз в 30 с, индикация).
* `main/Kconfig.projbuild` — все настройки `menuconfig`.
* `sdkconfig.defaults` — то, что обязательно для работы репитера
  (`CONFIG_LWIP_IP_FORWARD=y`, `CONFIG_LWIP_IPV4_NAPT=y`), чуть увеличенные
  буферы Wi-Fi и размер flash 4 МБ.
* `partitions.csv` — таблица разделов: приложению отдано 2 МБ (прошивка
  занимает ~780 КБ, так что в 1 МБ «по умолчанию» она бы почти не влезла).

Сама прошивка занимает около 780 КБ, свободного места в разделе приложения —
больше половины, есть куда добавлять свой код.

Сборка автоматически проверяется в GitHub Actions
(`.github/workflows/firmware.yml`) сразу для ESP-IDF v5.5 и v6.x, там же
можно скачать готовые файлы прошивки (артефакты сборки).

## English summary

ESP32-S3 Wi-Fi repeater firmware (ESP-IDF 5.5/6.x). It connects to one Wi-Fi
network as a station (the network it "receives") and simultaneously runs its
own SoftAP (the network it "serves"), sharing the uplink with its clients
through NAT (NAPT) and acting as a DHCP + DNS-forwarding gateway.

Build:

```bash
cd esp32/wifi-repeater
idf.py set-target esp32s3
idf.py menuconfig     # section "Wi-Fi repeater (ESP32-S3)"
idf.py -p /dev/ttyUSB0 flash monitor
```

Key points: single 2.4 GHz radio — the SoftAP channel follows the station's
uplink channel and throughput is roughly halved; broadcast/mDNS and IPv6 are
not forwarded; make sure the AP subnet (`REPEATER_AP_IP`, default
`192.168.4.1/24`) does not collide with the uplink subnet.

CI (`.github/workflows/firmware.yml`) builds the project with ESP-IDF v5.5 and
v6.x and uploads firmware binaries as artifacts, including a single merged
image (`esp32s3-wifi-repeater-merged.bin`) that can be flashed at offset `0x0`.
